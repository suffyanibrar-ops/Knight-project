# Knight Medical Billing — SEO Automation

## What it does

The existing Content Studio remains the editorial system. The SEO automation layer adds:

- live Jiro search and page extraction;
- evidence-based opportunity discovery through DeepSeek;
- an opportunity queue with accept/dismiss and transfer into the existing `content_workflows` pipeline;
- scheduled deterministic technical SEO audits with history;
- published-content refresh recommendations;
- an admin SEO Control Center at `/admin/seo`;
- a protected background tick endpoint;
- cron-driven due-post publishing and automation ticks;
- an isolated, loopback-only Jiro service.

Nothing generated by AI is auto-published. Every article still requires the existing human approval and scheduling workflow.

## Jiro

- Installed version: `0.4.0` from PyPI.
- Python: 3.12, isolated at `/home/knight/jiro/.venv`.
- MIT core; no Pro/cloud plan or paid Jiro feature is activated.
- Bound to `127.0.0.1:8010`, not exposed publicly.
- Runs under the `knight` user.
- Jiro's own auth is disabled because its free-tier feature gate currently rejects valid authenticated free keys as “Enterprise.” A private `X-Knight-Internal-Token` gate wraps the ASGI app instead; every request except `/` requires that header.
- Network access is loopback-only.
- Search defaults to DuckDuckGo with Bing/Brave/Google fallback. Datacenter CAPTCHA/blocking can make individual engines fail; failed queries are reported, never replaced with invented results.

### Licence note

Jiro's README says the MIT core is free for commercial and private use, while its pricing table marks “commercial use” as a paid Pro/Enterprise benefit. This implementation uses only the MIT basic search/scrape surface and has not activated Pro or cloud billing. The owner should confirm the intended commercial licensing interpretation directly with Jiro before treating this as a settled legal position.

### Uninstall

```bash
# Remove only the KNIGHT-SEO-AUTOMATION block from the knight user's crontab.
crontab -l | sed '/# KNIGHT-SEO-AUTOMATION-BEGIN/,/# KNIGHT-SEO-AUTOMATION-END/d' | crontab -
/home/knight/jiro/stop.sh
rm -rf /home/knight/jiro
```

Removing Jiro does not delete the existing website database. Disable the SEO automation setting in `/admin/seo` before uninstalling to avoid failed discovery runs.

## Jiro integration

`src/lib/jiro-client.ts`:

- `/health`
- `/search`
- `/scrape` (markdown)
- rejects non-public/private/loopback targets before scraping
- 25-second timeout
- bounded results and content
- never sends the token to the browser

`src/lib/search-research.ts` now prefers Jiro for the existing Content Studio research stage, then falls back to Serper or Google Custom Search only if configured. If no provider is available, the UI says so and the AI is not allowed to invent SERP facts.

## Opportunities

`src/lib/seo-automation.ts`:

1. Uses the seed query set in `DEFAULT_SEED_QUERIES`.
2. Calls Jiro search.
3. Optionally extracts the top public result pages with Jiro.
4. Sends only the collected evidence, existing article titles and known paths to DeepSeek.
5. Stores explainable factors, sources, competitor headings/excerpts, outline and internal-link suggestions.
6. Deduplicates by normalised topic/keyword.
7. Saves up to four opportunities per AI call; discovery makes several bounded calls and deduplicates to reach the configured limit (default 15) without truncating JSON.
8. Requires a human to accept or dismiss.

No search volume, difficulty, CPC, ranking, traffic or indexing metric is estimated.

## Background schedule

The server has no passwordless sudo, so the systemd timer requested in the specification could not be installed. Equivalent user-level cron jobs are installed instead:

```cron
@reboot /home/knight/jiro/start.sh >/dev/null 2>&1
* * * * * /home/knight/jiro/watchdog.sh >/dev/null 2>&1
*/5 * * * * /home/knight/jiro/publish-due.sh >> /home/knight/jiro/logs/publish-due.log 2>&1
*/15 * * * * /home/knight/jiro/automation-tick.sh >> /home/knight/jiro/logs/automation-tick.log 2>&1
15 2 * * * cd /srv/knight/current && SQLITE_PATH=/var/lib/knight/app.db BACKUP_DIR=/var/backups/knight/daily BACKUP_KEEP_DAYS=14 /usr/bin/node scripts/backup-sqlite.mjs >> /home/knight/jiro/logs/backup.log 2>&1
```

The minute-level job is `watchdog.sh`, which checks `/health` with the internal token and restarts Jiro if the process is dead or unhealthy. `@reboot` starts it immediately after boot. `publish-due.sh` runs the existing idempotent scheduled-publication script. `automation-tick.sh` calls:

```text
POST http://127.0.0.1:3000/api/admin/seo/automation/tick
X-Knight-Automation-Secret: <file-backed secret>
```

Cron secrets live in 0600 curl config files (`watchdog-curl.conf`, `automation-curl.conf`) rather than command-line arguments. A systemd timer can replace cron later if root access is available. The unit templates are:

```ini
# /etc/systemd/system/knight-seo-automation.service
[Unit]
Description=Knight SEO automation tick
After=network.target knight.service

[Service]
Type=oneshot
User=knight
Group=knight
WorkingDirectory=/srv/knight/current
EnvironmentFile=/etc/knight/knight.env
Environment=SQLITE_PATH=/var/lib/knight/app.db
ExecStart=/home/knight/jiro/automation-tick.sh
```

```ini
# /etc/systemd/system/knight-seo-automation.timer
[Unit]
Description=Run Knight SEO automation every 15 minutes

[Timer]
OnCalendar=*:0/15
Persistent=true

[Install]
WantedBy=timers.target
```

`systemctl daemon-reload && systemctl enable --now knight-seo-automation.timer` requires privileged access.

Daily database backup is scheduled at 02:15 UTC with 14-day retention in `/var/backups/knight/daily`. It is an unencrypted SQLite online backup; protect the backup directory and add encryption if the backup medium is shared.

## Security

- Jiro and the app stay on loopback.
- Jiro's token is never exposed to the browser.
- The automation tick uses a file-backed secret, not a query parameter.
- Admin APIs require an authenticated admin session.
- Scraped content is treated as untrusted evidence; it is not inserted into articles as instructions.
- URLs are restricted to http/https public targets.
- Content goes through the existing sanitizer and human review.
- Secrets are not committed.
- No new paid database or queue is used.

## Cost controls

- DeepSeek Flash only; no new AI provider.
- Maximum four opportunities per AI call, up to 15 per discovery run.
- Maximum four Jiro queries and two competitor extractions per discovery run by default.
- One discovery run per 24 hours by default.
- Daily AI discovery run cap.
- No paid Jiro plan activated.
- Search Console is optional and free.
- Existing deterministic checks are used where AI is unnecessary.

Actual DeepSeek cost depends on current token usage and pricing. The system does not claim a fixed cost.

## Known limitations / partial items

- Search Console is not authorized; performance cards remain unavailable.
- Jiro free-tier authenticated mode is broken upstream; loopback + custom token gate is used instead.
- Jiro commercial licensing terms are ambiguous between the MIT statement and the paid pricing table.
- The scheduled technical audit is a bounded deterministic crawl (up to 30 sitemap pages), while `/admin/seo` also retains the existing full manual crawl.
- Content refresh recommendations currently target published blog posts, not every static marketing page.
- AI-generated image recommendations and automatic media assignment are not implemented.
- No off-site backlink acquisition is performed.
- No systemd timer was installed due missing privileged access; user cron is active.
- No automatic AI publishing exists or will be enabled.
